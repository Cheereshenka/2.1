# Лабораторная работа №1 — «Три мешочка»

## 1. Назначение работы

Приложение моделирует игровой автомат с тремя виртуальными мешочками. Пользователь создаёт игровую сессию, вносит виртуальную монету, запускает раунд и выбирает один из трёх мешочков. Результат розыгрыша определяется выбранной стратегией автомата и номером раунда.

Главная учебная цель лабораторной работы — показать применение паттерна **«Цепочка обязанностей» (Chain of Responsibility)**. Один и тот же запрос передаётся по цепочке обработчиков, пока не будет найден обработчик соответствующего типа результата.

## 2. Аппаратная и программная конфигурация

Видеокарта и её характеристики в исходной лабораторной работе не указаны, поэтому они здесь не фиксируются.

### Почему Java 17

В курсовом проекте используется JDK 17, поэтому лабораторная приведена к той же версии Java. Это позволяет запускать обе работы в одной среде разработки без установки отдельной версии JDK. JavaFX 21 используется для графического интерфейса.

## 3. Что происходит при запуске программы

1. Класс `Launcher` запускает JavaFX-приложение `App`.
2. `App` создаёт окно программы, элементы управления и три кнопки-мешочка.
3. При создании новой игры создаётся объект `Player` с начальным балансом **3 виртуальные монеты**.
4. Класс `Game` управляет состоянием игровой сессии. Возможные состояния:
   - `READY` — можно начать раунд;
   - `CHOOSE` — нужно выбрать мешочек;
   - `DECIDE` — получен выигрыш и нужно решить, забрать его или рискнуть;
   - `FINISHED` — игра завершена.
5. При нажатии «Играть · 1 монета» класс `Player` списывает одну монету, а `Game` переводит игру в состояние `CHOOSE`.
6. При выборе мешочка вызывается **один и тот же метод** `Game.choose(strategy)` для всех трёх кнопок. Номер мешочка нужен только для записи в журнал.
7. `ActionChain` выбирает результат по вероятности. В зависимости от стратегии результат может быть:
   - выигрыш (`WIN`);
   - проигрыш (`LOSS`);
   - бесплатный второй шанс (`CHANCE`).
8. Затем результат проходит через цепочку:

```text
ActionChain
    ↓
LossHandler
    ↓
WinHandler
    ↓
ChanceHandler
```

9. Каждый обработчик проверяет, относится ли запрос к нему. Если нет — передаёт запрос следующему звену.
10. При выигрыше ставка удваивается и игра переходит в `DECIDE`.
11. При проигрыше ставка обнуляется, а игра возвращается в `READY`.
12. При результате `CHANCE` игрок получает возможность выбрать мешочек ещё раз без дополнительной оплаты.
13. При «Играть на выигрыш» вся текущая сумма снова становится ставкой.
14. При «Забрать и закончить» выигрыш возвращается в кошелёк, а сессия завершается.
15. `App` отвечает за отображение состояния, баланса, ставки, номера раунда и журнала событий.

## 4. Как работает паттерн «Цепочка обязанностей»

В проекте базовым звеном является абстрактный класс `Handler`. Каждый конкретный обработчик наследуется от него.

### `LossHandler`

Обрабатывает запрос `LOSS` и возвращает результат:

> «Мешочек пуст. Ставка потеряна.»

### `WinHandler`

Обрабатывает `WIN`. Множитель равен 2, поэтому текущая ставка удваивается.

### `ChanceHandler`

Обрабатывает `CHANCE` и возвращает сообщение о бесплатном повторном выборе.

Если в цепочку передать неизвестный тип, последний обработчик выбрасывает `IllegalArgumentException`. Благодаря этому ошибка не скрывается.

## 5. Стратегии автомата

| Стратегия | Вероятность выигрыша | Бесплатный шанс |
|---|---:|---:|
| Удержать | 55% в раундах 1–3, затем 35% | 15% |
| Обобрать | 12% | 15% |
| Дать надежду | 70% в раундах 1, 4, 7…; иначе 15% | 15% |

Оставшаяся вероятность соответствует проигрышу.

Выбранный пользователем мешочек не влияет на результат. Это сделано специально: лабораторная демонстрирует обработку события и паттерн проектирования, а не реализацию физической случайности выбора мешочка.

## 6. Основные классы

```text
Launcher
   ↓
App ─────────────→ Ui
   ↓
Game ────────────→ Player
   ↓
ActionChain
   ↓
Handler
 ├── LossHandler
 ├── WinHandler
 └── ChanceHandler
   ↓
Outcome
```

### `Player`

Хранит имя игрока, количество монет и число оплаченных раундов.

### `Game`

Содержит основную игровую логику: начало раунда, выбор мешочка, риск и вывод выигрыша.

### `ActionChain`

Определяет тип результата и запускает цепочку обработчиков.

### `Outcome`

Хранит результат розыгрыша: тип, множитель и текстовое сообщение.

### `App` и `Ui`

Отвечают за JavaFX-интерфейс и отображение данных пользователю.

## 7. Пример одного полного раунда

Допустим, баланс игрока равен 3 монеты.

```text
1. Нажимаем «Играть · 1 монета»
        ↓
2. Баланс: 3 → 2
        ↓
3. Ставка: 1 монета
        ↓
4. Игра переходит в CHOOSE
        ↓
5. Игрок выбирает мешочек №2
        ↓
6. ActionChain определяет результат
        ↓
7а. WIN → ставка 1 × 2 = 2 → DECIDE
или
7б. LOSS → ставка = 0 → READY
или
7в. CHANCE → бесплатный повторный выбор
```

Если получен выигрыш 2 монеты и пользователь выбирает «Забрать и закончить», эти 2 монеты возвращаются в кошелёк:

```text
Баланс: 2
Ставка: 2
      ↓
«Забрать и закончить»
      ↓
Баланс: 4
Ставка: 0
Состояние: FINISHED
```

## 8. Тестирование

В проекте предусмотрены модульные тесты `GameTest` и UI smoke-тест `UiSmokeTest`.

Проверяются:

- повторная ставка и вывод выигрыша;
- проигрыш;
- бесплатный второй шанс;
- отсутствие средств;
- запрет повторной оплаты во время активного раунда;
- обработка неизвестного типа результата;
- наличие трёх кнопок-мешочков в интерфейсе.

Запуск обычных тестов в Windows:

```powershell
.\mvnw.cmd test
```

Запуск UI-проверки:

```powershell
.\mvnw.cmd -Djavafx.smoke=true test
```

## 9. Запуск программы на нашем компьютере

1. Открыть проект в IntelliJ IDEA.
2. Проверить, что выбран **JDK 17**.
3. Дождаться загрузки Maven-зависимостей.
4. Запустить `Launcher.main()` или выполнить:

```powershell
.\mvnw.cmd javafx:run
```

Рабочим каталогом должна быть папка, содержащая `pom.xml`.

## 10. Краткое объяснение для защиты

> Лабораторная работа представляет собой JavaFX-приложение «Три мешочка». Пользователь играет с виртуальными монетами и получает один из трёх результатов: выигрыш, проигрыш или бесплатный шанс. Основная цель работы — реализовать паттерн «Цепочка обязанностей». Класс `ActionChain` формирует тип события и передаёт его через `LossHandler`, `WinHandler` и `ChanceHandler`. Каждый обработчик отвечает только за свой тип события, а если событие ему не подходит, оно передаётся следующему обработчику. Класс `Game` управляет состояниями игры и ставкой, `Player` хранит баланс, а JavaFX-классы отвечают за интерфейс. Работа адаптирована под используемый компьютер с Intel Core i7-12650H, 16 ГБ ОЗУ, Windows 10 и JDK 17.

## Внешний вид

Интерфейс упрощён: убраны декоративные изображения и лишние визуальные элементы. Используется плоская цветовая схема с тёмно-бирюзовым заголовком, светлым фоном и минимальными рамками. Функциональные элементы приложения сохранены.
